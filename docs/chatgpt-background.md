# ChatGPT 后台连接

1. 安装 Knowledge Atlas 0.1.3，打开右上角设置。
2. 在「ChatGPT 普通聊天」点击 Platform 链接，在自己的组织创建隧道并关联 ChatGPT 工作区；创建具备隧道 Read / Use 权限的运行密钥。不要使用管理员密钥作为运行密钥。
3. 把隧道 ID 和运行密钥填入应用。选择是否记住密钥、下次打开应用自动连接、关闭窗口后在菜单栏／托盘继续运行，点「保存并连接」。不需要安装 Node 或运行终端命令。
4. 等状态变成「已就绪」，点击 ChatGPT 插件链接，添加自定义 MCP，连接类型选 Tunnel，选自己的隧道，MCP 认证选 No authentication。本地 MCP 仍有 Bearer 认证，由内置运行程序提供；密钥不发送到 ChatGPT 对话中。
5. 在普通聊天中启用连接，先列地图，再读取测试地图。只有实际调用成功才完成账号端验收。

关闭窗口后，应用和隧道继续运行；从菜单栏／托盘打开窗口或完全退出。下次打开应用自动连接不等于电脑开机自启。主动「断开」不会删除密钥；「清除连接设置」会断开并移除系统凭据。退出会结束应用持有的隧道进程，异常退出则由应用在运行期间退避重启，网络中断由官方运行程序重连，不自动重复未知结果的写操作。

macOS 使用系统钥匙串，Windows 使用凭据管理器，Linux 使用 Secret Service。Linux 需要可用且已解锁的桌面凭据服务；若不可用，可取消「记住密钥」及自动连接，仅本次使用。应用不会退回明文文件保存运行密钥。JSON 设置仅保存隧道 ID、选项和环境变量引用。读取地图时，相关地图内容会作为工具结果发送给 ChatGPT。

内置 OpenAI `tunnel-client-runtime v0.0.20`，安装包携带其 Apache-2.0 LICENSE、NOTICE 和第三方许可证。构建脚本验证固定发行包 SHA-256 后提取，运行时不下载和执行新版本。运行程序使用本地 HTTP MCP，不需要插件分支中的 Node 转接器。

测试覆盖 UI 操作和保存失败、进程退出重启/主动停止、三平台构建、真实本地 MCP 认证与官方运行程序的健康探测；自动测试的云端为本地协议模拟，不是用户的 ChatGPT 账号。首次账号授权、绑定与远端实际调用仍需在用户电脑上完成。

参考：[OpenAI 安全隧道](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)、[官方运行程序](https://github.com/openai/tunnel-client/releases/tag/v0.0.20)
